# WukongAutoBench

Консольная утилита на C#, которая сама прогоняет **Black Myth: Wukong Benchmark Tool** (Steam) два раза:
CPU-тест и GPU-тест, а потом собирает результаты и характеристики компьютера в один отчёт.

## Требования

- Windows 10/11 x64
- .NET 8 SDK (для сборки) или .NET 8 Runtime (для готового exe)
- Steam с установленным Black Myth: Wukong Benchmark Tool
- Бенчмарк нужно **один раз запустить вручную** и закрыть: при первом старте он создаёт
  `GameUserSettings.ini` и компилирует шейдеры. Утилита правит существующий конфиг.

## Запуск

```
git clone <repo>
cd wukong-autobench
dotnet run -c Release
```

или собрать exe:

```
dotnet publish -c Release -r win-x64 --self-contained false -o out
out\WukongAutoBench.exe
```

Параметры:

| Параметр | Что делает |
|---|---|
| `--dir <путь>` | папка бенчмарка, если не нашлась автоматически |
| `--only cpu` / `--only gpu` | запустить только один из тестов |
| `--rt` / `--no-rt` | принудительно включить/выключить трассировку лучей в GPU-тесте |
| `--timeout <мин>` | таймаут на один проход (по умолчанию 20) |
| `--out <путь>` | папка для результатов (по умолчанию `results` рядом с exe) |

**Во время работы не трогайте мышь и клавиатуру** - меню бенчмарка проходится эмуляцией кликов.
Весь прогон занимает примерно 10 минут.

## Как это работает

1. Папка бенчмарка ищется через реестр Steam (`SteamPath`) -> `libraryfolders.vdf` -> `appmanifest_3132990.acf`.
2. Делается бэкап `b1\Saved\Config\Windows\GameUserSettings.ini`, в него записываются настройки прохода.
   Настройки дублируются в двух местах: в строке `UISettingData` (значения меню) и в `[ScalabilityGroups]` (`sg.*` движка UE).
3. Бенчмарк запускается через `steam://rungameid/3132990`. Командной строки для старта теста у него нет,
   поэтому утилита активирует окно игры и по кругу жмёт Enter (заставка) -> "Тест быстродействия" -> "Подтвердить".
4. После прогона бенчмарк пишет JSON в `%TEMP%\b1\BenchMarkHistory\Tool\<unix time>`. Как только там появляется
   новый файл, который нормально парсится, проход считается завершённым, процесс игры убивается
   (если закрыть штатно, игра перезапишет ini своими значениями).
5. После обоих проходов конфиг восстанавливается из бэкапа (в том числе при Ctrl+C или если программа упала -
   при следующем запуске бэкап будет найден и восстановлен).

Характеристики ПК берутся из WMI (CPU, GPU, драйвер, RAM, материнская плата, ОС, разрешение экрана),
объём видеопамяти - из реестра драйвера, т.к. `AdapterRAM` в WMI 32-битный и на картах больше 4 ГБ показывает неправду.

## Результаты

Отчёт выводится в консоль и сохраняется в `results\<дата_время>\`:

- `report.md` - характеристики ПК, таблица результатов обоих тестов и применённые настройки
- `cpu_raw.json`, `gpu_raw.json` - исходные файлы бенчмарка

В таблице: средний / 95% / минимальный / максимальный FPS (из файла бенчмарка), плюс посчитанные
по покадровым записям 1% low, среднее время кадра, среднее время кадра на CPU и на GPU и доля кадров,
где процессор считал кадр дольше видеокарты ("упор в CPU"). Последняя колонка нужна, чтобы проверить,
что CPU-тест действительно упирается в процессор, а GPU-тест - в видеокарту.

## Выбор настроек

Общее для обоих тестов: VSync выключен, ограничение FPS выключено, генерация кадров (Frame Generation) выключена.
С VSync/лимитом FPS упирается в частоту монитора, а генерация кадров добавляет "нарисованные" кадры,
которые не отражают реальную производительность ни CPU, ни GPU. Разрешение экрана и режим окна не меняются -
бенчмарк сам выбрал их под монитор при первом запуске, а подмена индекса `ScreenResolution` на чужой
мониторе может сломать запуск. Апскейлер (DLSS/FSR/XeSS/TSR) тоже не трогаю: какие из них доступны,
зависит от видеокарты, и неподходящее значение роняет бенчмарк.

### CPU-тест

| Параметр | Значение |
|---|---|
| Качество графики | низкое (все группы 1, `sg.*` = 0) |
| Масштаб рендеринга | 50% |
| Трассировка лучей | выкл. |
| Размытие в движении | выкл. |

Задача - сделать так, чтобы видеокарта успевала отрисовать кадр быстрее, чем процессор его подготовит.
Масштаб 50% уменьшает число пикселей в 4 раза, минимальные тени, GI, отражения и постобработка
убирают основную работу GPU. При этом логика, анимация, стриминг и draw calls остаются на процессоре,
поэтому FPS упирается в CPU. Трассировка выключена, т.к. это почти чистая нагрузка на GPU.

### GPU-тест

| Параметр | Значение |
|---|---|
| Качество графики | кинематографическое (все группы 5, `sg.*` = 4) |
| Масштаб рендеринга | 100% (нативное разрешение) |
| Трассировка лучей | вкл. на NVIDIA RTX, иначе выкл. |
| Размытие в движении | вкл. |

Максимальное качество всех групп, рендер в полном разрешении экрана без понижения, плюс размытие в движении
(тоже постобработка на GPU). Трассировка лучей даёт самую большую нагрузку на видеокарту, но включается
автоматически только на NVIDIA RTX: на других картах её либо нет, либо тест растягивается в разы.
Если с RT бенчмарк вылетает или закрывается без результата, проход автоматически повторяется без RT.
Поведение можно переопределить `--rt` / `--no-rt`.

## Ограничения

- Координаты кнопок меню заданы в долях окна (`BenchmarkRunner.cs`) и рассчитаны на 16:9.
  На ультрашироких мониторах может понадобиться их поправить.
- Окно игры должно быть на переднем плане, поэтому компьютер во время теста лучше не трогать.
